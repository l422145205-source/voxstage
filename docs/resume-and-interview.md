# 简历条目与面试讲解

**VoxStage：面向游戏与动画的可控对白制作 Agent**　个人项目

技术：Python / Qwen3-TTS / Qwen3-ASR / FastAPI / FFmpeg

- 面向角色对白生产，设计包含角色音色、台词、语气、非重叠时间槽和尝试预算的结构化 IR，接入 Qwen3-TTS，完成逐句生成、试听及 WAV/SRT/时间轴资产导出。
- 构建独立 ASR 内容核对与音频约束检查，结合 CER、关键字保护、削波和时长诊断，设计按失败原因重生成的有界循环；通过有限保音高加速与采样点校验处理时间槽约束，避免截断台词。
- 通过独立 worker 隔离 TTS/ASR 的 Transformers 版本冲突，使用内容指纹与 SHA256 复核实现增量制作；真实四句场景中，改一句仅新增一次合成，其余三句复用，完整重跑新增模型调用为零。

可选实验句：在 16 条预先冻结的中英文脚本探针上对比首次合成、时长适配和有界重生成，满足配置检查阈值的样本分别为 12、15、16 条，保留逐句真实音频和失败记录。

指标表述必须保留小规模探针和自动检查范围，不能写成自然度、情绪准确率或线上内容正确率。项目由 AI 编程工具辅助实现，投递前应能解释核心代码、模型接口、缓存失效与实验限制。

## 两分钟介绍

我做的是游戏或动画对白资产生产中的一段工作流：同一角色固定预设音色，每句台词有明确的内容和时长约束。合成后用没有参考台词提示的 ASR 核对，再检查声学和时间条件。超长可以小幅保音高加速，但超过范围必须重生成或交给人复核。

工程重点是把模型输出变成可检查、可增量重建的声音资产。两个官方模型包要求不同 Transformers 版本，所以我用进程协议隔离；生成参数、模型版本和种子构成内容指纹，复用前检查音频哈希。修改一句不会整段重新生成。

## 面试追问

1. **为什么 ASR 不传参考台词？** 若把参考内容加入上下文，可能使识别偏向目标，无法作为独立内容核对。即使不传参考，模型家族共同偏差仍未排除。
2. **为什么不能用 CER 代表听感？** CER 只比较文字，情绪、自然度和说话人相似度需要不同评估，当前没有做人工听评。
3. **为什么有保护词？** 较长台词漏掉一个否定词也可能低于平均 CER 阈值，因此允许作者指定必须保留的词；该机制是显式规则，文字变体可能误报。
4. **如何避免强行满足时长？** 加速有明确上限，变换后再核对，按采样点检查不得侵入下一句；不截断台词。
5. **缓存失效如何确定？** 文字、音色、指令、种子和模型配置变化会改变原始声音指纹；ASR 缓存还绑定音频哈希；时长编辑可复用原始音频。
6. **Agent 是否使用 LLM 自由规划？** 当前制作策略是确定性的有界工作流，基础模型负责生成与识别。不能声称实现了通用自主规划或训练了配音模型。
7. **最有说明力的失败是什么？** 一个英文候选内容一致但持续 7.52 秒，超出时间槽；重生成后变为 3.04 秒。另一个样本 ASR 将 promised 写成 promise，仍在默认阈值内，说明自动通过不等于逐字正确。
